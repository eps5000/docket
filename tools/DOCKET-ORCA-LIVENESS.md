# Scoped Docket and Orca liveness inspection

`docket-orca-liveness.mjs` is a read-only, local coordinator check for one Docket lead run, its recorded Orca Dispatch, one selected Epic, and one explicitly mapped Orca supervisor automation. The coordinator supplies an independently reviewed mapping file and the exact automation and workspace IDs. The tool does not infer that an automation belongs to an Epic from its name, prompt text or path.

```powershell
node tools/docket-orca-liveness.mjs --run-id run_... --dispatch-id ctx_... --epic-id GF-231 --automation-id <Orca UUID> --workspace-id '<Orca repo ID>::C:/exact/supervisor/worktree' --mapping-file C:/reviewed/epic-supervisors.json
```

The local mapping file has the shape `{"version":1,"entries":[{"epic_id":"GF-231","automation_id":"<Orca UUID>","workspace_id":"<Orca repo ID>::C:/exact/supervisor/worktree"}]}`. Entries must be unique by Epic, automation and workspace. A missing, malformed, conflicting or mismatched entry holds supervisor assessment before any automation or supervisor-worktree read. The file is an operator declaration, **not** owner approval or a restart receipt. Independently review the selected Epic's owner scope, current automation prompt, target worktree and producer custody before using it. The disabled generic, historical GF-231 and one-date GF-457 automations are not mappings for GF-310 or any other Epic.

The result is one bounded `parked`, `problem`, or `hold` category. A problem may include a suggested `update_run_status.dispatch_observation` state for the coordinator to review and record through Docket's existing authenticated API. The tool never writes that observation, sends a wake, changes a claim, starts or edits an automation, dispatches a replacement, releases a resource, or stops a process. It emits no command lines, paths, titles, prompts, run IDs, process IDs, or private content.

It requires the exact parked Docket run and paused lease from `/api/agents`, the same run and Dispatch in Docket's complete, fresh `orca-audit` target list of at most 160 eligible targets, and the item's actual `epic` field matching the selected Epic. Audit targets are identity-only cursors: they do not contain current run state. A missing or duplicate exact run in the bounded `/api/agents` view is unknown, not evidence of completion. A project pause, active cited owner decision, person wait or unanswered owner question stays an intentional hold. A coordinator wait with no named wake or an overdue deadline becomes one problem. A failed or exited Orca worker becomes a custody problem only after `worker-show` matches the recorded Dispatch, Orca parent run, host and worktree path. Missing or mismatched worker evidence is unknown. Automation and supervisor worktree reads happen only after the Docket item/Epic, Orca worker identity and explicit mapping pass. The result still says `automation_scope: operator_selected`: a file declaration cannot verify owner approval. Disabled, missing target and overdue scheduled states are reported only from Orca's readback. A `supervisor_overdue` result means Orca's `nextRunAt` is more than five minutes past with no later recorded run. It is a configuration problem for the coordinator, not proof that a particular process died. An unavailable read, stale audit, incomplete inventory or unmapped Epic is a hold. A configured automation is not proof that a supervisor is currently running.

This inspection is a source lane for #187, not a supervisor restart. Before any selected Epic is restarted, the coordinator must verify the owner's active scope decision, an explicit per-Epic automation/worktree mapping, the responsible automation's actual prompt and target, the project's freeze boundary, and absence of a competing producer. A disabled generic or prior-Epic automation is not an implicit mapping for a new Epic. A restart would be a separate Orca action with an exact receipt and review. A protected HOST HOLD or unknown descendant stays held; a failed worker alone never authorizes a restart, claim release, terminal cleanup, or host action.
