# Jira capability research for a local agent work tracker

Reviewed 2026-11-06. Sources are Atlassian and MCP primary documentation. Jira Cloud behavior varies by product, plan, and project/space configuration. “Work item” is Atlassian's current UI term; API names and many JQL expressions still use “issue” or “project.” [Terminology and search](https://support.atlassian.com/jira-software-cloud/docs/find-specific-work-items/)

## Scope of comparison

This compares the capabilities relevant to one person's agent-led software/product work. Jira Service Management adds requests, SLAs, incident/change workflows, and Assets; Jira Product Discovery adds ideas, insights, scoring, and stakeholder roadmaps. Those are separate products, not a baseline Jira Software feature set. [Jira Product Discovery](https://www.atlassian.com/software/jira/product-discovery/features)

| Area | What Jira Cloud provides | Implication for this product |
| --- | --- | --- |
| Work structure | Projects/spaces; default Epic → Story/Task/Bug → Subtask hierarchy; parent/child work items; typed fields, priority, assignee, labels. Higher hierarchy and configuration vary by plan and space type. [Work types](https://support.atlassian.com/jira-cloud-administration/docs/what-are-issue-types/) | Support durable outcomes and small executable tasks, but choose whether every agent step belongs in the durable tracker. |
| Execution | Configurable statuses, transitions, conditions, validators, and permissions; boards and ranked backlogs; Scrum sprints or Kanban flow. [Workflows](https://support.atlassian.com/jira-cloud-administration/docs/configure-advanced-issue-workflows/), [backlog](https://support.atlassian.com/jira-software-cloud/docs/enable-the-backlog/) | Start with one clear workflow and enforce transition rules in the server. Keep optional iteration planning separate. |
| Relationships | Typed, directional issue links including Blocks, Duplicate, and Relates. Parentage and rank are different concepts from blocking. Jira's single-space timeline shows only Blocks links from that space. [Issue links API](https://developer.atlassian.com/cloud/jira/platform/rest/v3/api-group-issue-links/), [timeline dependencies](https://support.atlassian.com/jira-software-cloud/docs/create-or-remove-dependencies-on-your-timeline/) | Model explicit directed blockers and detect cycles. Show cross-project blockers even if Jira's simpler timeline does not. |
| Time planning | Dates, estimates, sprints, releases/versions, timeline bars, and progress rollups. Premium/Enterprise Plans add multi-source planning, capacity and autoscheduling; plan edits are a sandbox until committed. [Plans](https://support.atlassian.com/jira-software-cloud/docs/build-out-your-plan-in-advanced-roadmaps/), [scheduling](https://support.atlassian.com/jira-software-cloud/docs/estimate-and-schedule-issues-in-advanced-roadmaps/), [versions](https://support.atlassian.com/jira-software-cloud/docs/enable-releases-and-versions/) | Separate committed dates from computed forecasts, record assumptions, and make dependency impact visible. Do not imply precise completion dates without estimates/capacity. |
| Finding work | Field/text search, JQL, filters, saved and shared searches, board quick filters. [Search](https://support.atlassian.com/jira-software-cloud/docs/search-for-work-items-in-jira/), [saved searches](https://support.atlassian.com/jira-software-cloud/docs/what-is-a-saved-search/) | Provide dependable indexed search plus a small, explicit filter language/API for agents. |
| Reporting | Dashboards/gadgets and reports for cycle time, cumulative flow, burndown/burnup, velocity, epic/release progress, and created vs resolved. Applicability depends on Scrum/Kanban and available data. [Reports](https://support.atlassian.com/jira-software-cloud/docs/generate-a-report/), [gadgets](https://support.atlassian.com/jira-cloud-administration/docs/use-dashboard-gadgets/) | Prioritize actionable current-state views: blocked, stale, review ready, throughput, and trend. Defer Scrum metrics unless the user uses sprints. |
| Agent activity | Jira offers a For You agent-session list and Agents dashboard for linked, supported agent experiences; Rovo and paid-plan prerequisites apply. This does not automatically cover arbitrary local subagents. [Sessions](https://support.atlassian.com/jira-software-cloud/docs/view-and-manage-agent-sessions-in-jira/), [dashboard](https://support.atlassian.com/jira-software-cloud/docs/use-the-agents-dashboard/) | First-class local run/session records and parent-child delegation are a key differentiator. |
| Collaboration and evidence | Descriptions, comments, mentions, watchers/notifications, attachments, links to Confluence pages/live docs and external files, activity history, and worklogs. Jira's Docs tab is backed by Confluence. [Attachments](https://support.atlassian.com/jira-software-cloud/docs/add-files-images-and-other-content-to-describe-an-issue/), [Docs](https://support.atlassian.com/jira-software-cloud/docs/pages-for-next-gen-projects/), [activity](https://support.atlassian.com/jira-software-cloud/docs/what-are-the-different-types-of-activity-on-an-issue/) | Let reviewers open versioned artifacts and review evidence from a task. Decide where document bytes live; a URL alone is insufficient for offline review. |
| Delivery links | With a connected development tool, Jira can show branches, commits, PRs, builds, deployments and feature flags tied to keys. [Development information](https://support.atlassian.com/jira-software-cloud/docs/view-development-information-for-an-issue/) | Store structured links and verification provenance; do not equate a PR link with merged/deployed/accepted. |
| Automation | Event/schedule triggers, conditions, actions such as editing/linking/assigning, and per-flow run logs. [Triggers](https://support.atlassian.com/cloud-automation/docs/jira-automation-triggers/), [conditions](https://support.atlassian.com/cloud-automation/docs/jira-automation-conditions/), [actions](https://support.atlassian.com/cloud-automation/docs/jira-automation-actions/), [audit](https://support.atlassian.com/cloud-automation/docs/view-execution-data-for-a-rule/) | A small event stream and rules for stale work, review alerts, and blocker release may suffice initially. |
| Administration | Team-managed spaces favor local simplicity; company-managed spaces support shared schemes, complex permissions, and workflows. Jira has distinct admin audit logs for configuration; they do not cover every work event. [Space types](https://support.atlassian.com/jira-software-cloud/docs/what-are-team-managed-and-company-managed-spaces/), [audit](https://support.atlassian.com/jira-cloud-administration/docs/audit-activities-in-jira-applications) | Keep initial settings simple, but log every task/document/review mutation with actor and timestamp. |
| Data exchange | Jira supports CSV and JSON import and export paths, with separate attachment handling. [Import/export overview](https://support.atlassian.com/jira-cloud-administration/docs/import-and-export-your-data-to-and-from-jira-cloud/) | Define loss-aware Jira migration and a complete local backup/restore format before replacing existing records. |

## Important limitations and lessons

1. **A hierarchy is not a dependency graph.** Only a directed blocker should stop downstream work. A related link or parent does not imply “wait.” [Atlassian dependency semantics](https://support.atlassian.com/jira-software-cloud/docs/create-or-remove-dependencies-on-your-timeline/)
2. **A timeline is not a forecast by itself.** Dates can be entered manually; capacity and auto scheduling are separate planning features. Forecasts must expose missing estimates and uncertain agent availability. [Plans](https://support.atlassian.com/jira-software-cloud/docs/build-out-your-plan-in-advanced-roadmaps/)
3. **Jira's agent reports are integration-dependent.** They require linked sessions and supported agent experiences; a local tracker should accept agent start/heartbeat/finish/review events directly. [Agents dashboard](https://support.atlassian.com/jira-software-cloud/docs/use-the-agents-dashboard/)
4. **Documents are often separate content.** Jira can attach files and embed/link Confluence, but Confluence remains the document system behind the Docs feature. [Docs](https://support.atlassian.com/jira-software-cloud/docs/pages-for-next-gen-projects/)
5. **The API is broad but is still a remote service.** REST v3 supports work records and integrations, and Atlassian documents multiple rate limit mechanisms. The local replacement's main reliability benefit will come from a single known endpoint and local data, not from cloning Jira's entire API. [REST API](https://developer.atlassian.com/cloud/jira/platform/rest/v3/intro), [rate limits](https://developer.atlassian.com/cloud/jira/platform/rate-limiting/)

## Local evidence and working assumptions

During discovery, one Jira CLI route returned `AUTH_REQUIRED` while a separately authorized MCP route could read the same work item. This demonstrates a client-specific access failure, not a Jira-wide outage. A durable Jira item can capture outcome, owner decisions, source document links, planning boundaries, comments, and status, but it does not automatically expose the live state of local subagents.

One existing workflow uses Jira for roadmap priority, real cross-feature Blocks links, and durable follow-ups; a temporary PR feature sheet holds short-lived implementation tasks and their local blockers. Treat that as an example to test, not a universal rule for every project.

## MCP and Docker implications to validate

MCP supports `stdio` and Streamable HTTP. The latter is an independent server endpoint capable of multiple client connections; it fits a shared Docker service. The specification calls for Origin validation, localhost binding for local use, and authentication. [MCP transports](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports) Tool schemas and structured results are part of the MCP tool contract. [MCP tools](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)

“Local” has multiple network positions: host agents can use a loopback-published port; containerized agents may need a Docker network address or host gateway. The endpoint, authentication and permitted origins must be verified against the actual agent clients before choosing a transport/configuration. A browser UI and MCP clients may need different access paths to the same backend.

### Installed client feasibility check, 2026-11-06

`codex`, `claude`, and `orca` executables are present on this Windows host. Both installed Codex and Claude expose `mcp` CLI commands. [Official OpenAI Docs](https://learn.chatgpt.com/docs/extend/mcp?surface=cli) document Codex Streamable HTTP MCP configuration through a URL and optional bearer-token environment variable. [Claude Code documentation](https://code.claude.com/docs/en/mcp) documents HTTP MCP servers and local/project/user configuration scopes. This supports connecting the installed clients to the service; no model API integration is needed for task tracking.

Orca's local CLI guide confirms it can launch Codex or Claude in a worktree as a chat or terminal. It does not establish that every Orca chat/worker surface automatically inherits the user's MCP server configuration. Verify each intended Orca launch surface end to end during the pilot, and use a local client-side bridge only if a specific surface needs one. Do not infer a live subagent heartbeat from a log entry supplied by its parent agent.
